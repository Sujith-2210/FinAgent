
# 📘 FinAgent — Project Documentation

**Title:** *FinAgent: A Privacy-Preserving Multi-Agent Financial Intelligence System using Model Context Protocol (MCP)*

---

## 1️⃣ What is This Project?

### 🔹 Problem Statement

Existing AI-based financial assistants:

* Provide **generic advice**
* Lack **context awareness**
* Do not support **multi-agent reasoning**
* Offer **no transparency or explainability**
* Often compromise **user privacy** by sending data to external APIs

There is **no system** that combines:

> **Multi-agent AI + real financial context + privacy + explainability**

---

### 🔹 Proposed Solution (FinAgent)

FinAgent is a **context-aware, privacy-preserving financial intelligence system** that:

* Uses **Model Context Protocol (MCP)** to manage structured financial data
* Employs **multiple specialized AI agents** to reason collaboratively
* Runs **locally using open-source LLMs** to protect privacy
* Produces **explainable, auditable financial recommendations**

---

### 🔹 Core Idea (One Line)

> *FinAgent uses MCP-backed financial context and multi-agent AI to deliver personalized, explainable, and privacy-first financial guidance.*

---

| Agent overreach   | Context access rules |
| LLM misuse        | Local inference only |

```
✔ Bank balance masked
✔ Credit score bucketed
✔ No external API calls
```

## 1️⃣ Orchestrator Agent (Router)

### 🎯 Purpose

Decides **which agents to invoke** and in what order.
❌ Does NOT perform calculations
❌ Does NOT generate final answers

---

### 🔹 System Prompt

```text
You are the Orchestrator Agent in a multi-agent financial intelligence system.

Your task is to:
- Understand the user's intent
- Decide which specialized agents are required
- Determine execution order
- Specify what context each agent must read

Rules:
- Do NOT perform financial calculations
- Do NOT generate user-facing advice
- Do NOT access raw financial values
- Output must be structured JSON only
- Minimize the number of agents invoked
```

---

### 🔹 Input

```json
{
  "user_query": "...",
  "available_agents": ["finance_reasoning", "knowledge", "explainability", "alert"],
  "context_summary": {
    "has_assets": true,
    "has_liabilities": true,
    "has_goals": true
  }
}
```

---

### 🔹 Output

```json
{
  "execution_plan": [
    {
      "agent": "finance_reasoning",
      "context_required": ["net_worth", "liabilities", "cash_flow"]
    },
    {
      "agent": "knowledge",
      "context_required": ["tax_rules", "market_conditions"]
    },
    {
      "agent": "explainability",
      "context_required": ["agent_outputs"]
    }
  ],
  "reason": "User query requires financial evaluation and external rule grounding"
}
```

---

### 📄 Paper Rationale

> The orchestrator agent enforces separation of concerns by routing tasks to domain-specific agents, reducing cognitive overload and preventing unnecessary access to sensitive context.

# 🧩 FinAgent — MCP Context Schema (FINAL)

---

## 1️⃣ MCP Context Philosophy (Important to Understand)

In FinAgent, **MCP is NOT just data**.
It is a **versioned, structured, governed memory system**.

### Core principles:

* Context is **read-only by default**
* Agents must **declare intent** to read/write
* Context is **layered**
* Sensitive values are **masked before LLM access**
* Every update is **versioned & auditable**

---

## 2️⃣ Top-Level MCP Context Object

```json
{
  "context_id": "uuid",
  "user_id": "uuid",
  "created_at": "ISO-8601",
  "last_updated": "ISO-8601",
  "context_version": 7,
  "privacy_level": "HIGH",
  "layers": { }
}
```

📄 **Paper language**:

> We model user state as a versioned MCP context object composed of semantically isolated layers.

---

## 3️⃣ MCP Context Layers (Core Design)

### 🔹 Layer 1: User Financial Context

**Source:** Fi MCP (fi-mcp-dev)

```json
"user_financial_context": {
  "source": "fi-mcp-dev",
  "last_sync": "ISO-8601",
  "data": {
    "income_profile": {
      "monthly_income_band": "HIGH | MEDIUM | LOW",
      "income_stability": "STABLE | VARIABLE"
    },
    "assets_profile": {
      "net_worth_band": "LOW | MEDIUM | HIGH",
      "asset_classes": ["MF", "EPF", "STOCKS", "BANK"]
    },
    "liabilities_profile": {
      "has_loans": true,
      "debt_intensity": "LOW | MEDIUM | HIGH"
    },
    "credit_profile": {
      "credit_score_band": "POOR | FAIR | GOOD | EXCELLENT",
      "credit_utilization_band": "LOW | MEDIUM | HIGH"
    }
  }
}
```

🔐 **Privacy note**:
Raw values (₹, account numbers) are **never stored here** — only bands.

```json

    "agent_working_memory",
```

📄 **Paper sentence**:

## 5️⃣ Context Update Rules

| Rule         | Description                              |
| ------------ | ---------------------------------------- |
| Versioning   | Every write increments `context_version` |
| Immutability | Past versions are read-only              |
| Masking      | Raw values never enter LLM prompts       |
| Expiry       | Working memory expires per session       |
| Audit        | All writes are logged                    |
